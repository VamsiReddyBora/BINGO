1. EXECUTIVE SUMMARY & VERIFICATION OVERVIEW
--------------------------------------------------------------------------------
Following the verification and merge of commit `11dc7a4` (tag `v1.4`), which resolved
defects BUG-017 through BUG-023 from Bug Report #005, an exhaustive, multi-module audit
was conducted across the entire native Android application codebase.

In strict adherence to project directives:
  • Scope is restricted 100% to native Android files (`app/src/main/java/...`).
  • Web application files are completely excluded.
  • The audit is organized into clear functional modules:
      1. Network Handling & Session Lifecycle
      2. Gameplay Engine & Navigation State Machine
      3. In-Game Lifecycle & Surrender Routing
      4. UI & Visual Presentation
      5. Nearby / Local LAN P2P Network
      6. Auth, Session & Local Persistence
  • Draw mechanics are verified as permanently decommissioned (only Winner, Runner,
    and Offline stamps apply).

Full Test Suite Baseline Verification:
  • 26 unit and simulation test suites executed.
  • 100% PASS RATE (`./gradlew testDebugUnitTest` BUILD SUCCESSFUL in 963ms).
  • All 7 previous fixes from commit `11dc7a4` verified intact and functioning.

While commit `11dc7a4` successfully corrected group match surrender aborts, non-host
leave checks, acting host promotions, and theme persistence synchronization, this
audit discovered 7 new critical and edge-case defects across the modules. These include
blank winner/winReason assignments on forfeit paths, disconnection handling bypassing
Manual Board Design screens, unreachable 3-miss forfeit loops in 2-player matches,
infinite rejoin loops after host kicks, and hardcoded losses on LAN host disconnects.

DEFECT ID: BUG-024
SEVERITY : HIGH
MODULE   : Network Handling & Session Lifecycle
FILES    : RootNavGraph.kt (lines 2198-2207, 2259-2266, 3900-3910)
--------------------------------------------------------------------------------
DESCRIPTION:
On match termination triggered by opponent forfeit, host departure, or consecutive
turn timeouts, `winnerPlayerId` and `activeWinReason` are never populated. They remain
empty strings `""`. Consequently, when players review boards post-match, nobody is
awarded the "WON!" stamp badge, and any client requesting state synchronization via
`SYNC_REQUEST` receives an empty winner ID, breaking authoritative outcome resolution.

ROOT CAUSE:
In commit `11dc7a4`, `winnerPlayerId = if (wonByForfeit) myUid else ""` and
`activeWinReason = "Opponent Left"` were added to non-host `LEAVE` (lines 2321-2322)
and `SURRENDER` (lines 2124-2125). However, three other critical game-over paths were
missed:

1. `HOST_LEFT` when active remaining <= 1 (lines 2259-2266):
```kotlin
if (activeRemaining.size <= 1 || isUsingP2p) {
    isGameOver = true
    val wonByForfeit = if (isUsingP2p) false else (activeRemaining.any { it.id == myUid } || participants.size <= 2)
    didPlayerWin = wonByForfeit
    isDrawMatch = false
    isRunnerMatch = false
    recordFinishedMatch(wonByForfeit)
    com.bingo.multiplayer.domain.network.OngoingMatchStore.clearOngoingMatch(context)
    opponentDisconnectMessage = if (isUsingP2p) "Host disconnected. LAN match ended." else "All opponents left the game."
    // MISSING: winnerPlayerId and activeWinReason assignment!
}
```

2. `PLAYER_DISCONNECTED` when misses >= 3 (lines 2198-2207):
```kotlin
if (activeRemaining.size <= 1 && misses >= 3) {
    isGameOver = true
    val wonByForfeit = activeRemaining.any { it.id == myUid } || participants.size <= 2
    didPlayerWin = wonByForfeit
    isDrawMatch = false
    isRunnerMatch = false
    recordFinishedMatch(wonByForfeit)
    com.bingo.multiplayer.domain.network.OngoingMatchStore.clearOngoingMatch(context)
    opponentDisconnectMessage = "Opponent disconnected. You win by forfeit!"
    // MISSING: winnerPlayerId and activeWinReason assignment!
}
```

3. Turn timer disconnect loop when misses >= 3 (lines 3900-3910):
```kotlin
if (activeRemaining.size <= 1 && misses >= 3) {
    isGameOver = true
    val wonByForfeit = activeRemaining.any { it.id == getLocalUid() } || participants.size <= 2
    didPlayerWin = wonByForfeit
    isDrawMatch = false
    isRunnerMatch = false
    recordFinishedMatch(wonByForfeit)
    com.bingo.multiplayer.domain.network.OngoingMatchStore.clearOngoingMatch(context)
    opponentDisconnectMessage = "Opponent disconnected. You win by forfeit!"
    // MISSING: winnerPlayerId and activeWinReason assignment!
}
```

USER-FACING IMPACT:
1. In `GameScreen.kt` (lines 978-988):
```kotlin
val isWinnerSelected = !isSelectedDisconnected && LobbyLifecycleEngine.isPlayerIdMatch(selectedReviewPlayerId, winnerPlayerId)
```
Because `winnerPlayerId` is `""`, `isWinnerSelected` evaluates to `false` for every
player. Even though the surviving player won by forfeit, inspecting opponents' boards
marks everyone as `LOST!` or `OFFLINE`, and no player ever displays `$reviewName WON!`.
2. When a reconnecting peer issues `SYNC_REQUEST`, line 2434 transmits `winnerPlayerId = if (isGameOver) winnerPlayerId else ""`
(which is `""`). The peer's `GAME_SYNC` handler (line 1955) skips authoritative outcome
reconciliation and falls back to line 1970 `evaluateMatchOutcome()`, which does not
detect a forfeit, corrupting the match state.

REMEDIATION:
Assign `winnerPlayerId`, `activeWinReason`, and `activeRunnerPlayerIds` in all 3 forfeit blocks:
```kotlin
winnerPlayerId = if (wonByForfeit) myUid else ""
activeWinReason = "Opponent Left" // or "Opponent Disconnected"
activeRunnerPlayerIds = emptyList()
```

DEFECT ID: BUG-025
SEVERITY : HIGH
MODULE   : Gameplay Engine & Navigation State Machine
FILES    : RootNavGraph.kt (lines 2162, 2239, 2308)
--------------------------------------------------------------------------------
DESCRIPTION:
During manual board creation on `Screen.ManualBoardDesign.route`, if a client disconnects,
leaves, or surrenders, the disconnect handler treats the match as NOT in game. The
surviving client is abruptly ejected to the Main Menu (on host departure) or permanently
stranded on "Waiting for other players to finish board design..." (on non-host departure).

ROOT CAUSE:
In `RootNavGraph.kt`:
Lines 2162 and 2239 define `inGame` strictly as:
```kotlin
val inGame = (destinationRoute == Screen.Game.route)
```
However, across the rest of `RootNavGraph.kt` (lines 361, 418, 487, 623, 636, 1391, 1485),
in-game state is consistently defined as:
```kotlin
val isInGame = currentDest == Screen.Game.route || currentDest == Screen.ManualBoardDesign.route
```

When manual board mode is chosen:
1. Host broadcasts `START_GAME` with `isManualBoard = true`.
2. All players navigate to `Screen.ManualBoardDesign.route` to arrange cells 1..25.
3. If the Host departs or drops connection during this stage:
   `inGame` evaluates to `false`.
   Line 2296 `else if (!inGame)` triggers:
   ```kotlin
   Toast.makeText(context, "Host left the lobby.", Toast.LENGTH_LONG).show()
   disconnectRoom()
   navController.navigate(exitDest)
   ```
   The guest is booted out to the Main Menu with Toast "Host left the lobby" even though
   a competitive match had already started! No forfeit win is recorded.
4. If a Guest departs:
   Line 2308 checks `if (inGame && !isGameOver ...)`.
   Because `inGame` is `false`, line 2308 is skipped entirely!
   `activeRemaining.size <= 1` is never checked.
   The surviving player finishes arranging their board, and in `ManualBoardDesignScreen`:
   ```kotlin
   val expectedUids = participants.map { it.id }.filter { it.isNotBlank() }.toSet()
   val allReady = expectedUids.isNotEmpty() && expectedUids.all { allPlayerBoards.containsKey(it) }
   ```
   Because the departed guest never submits a board, `allReady` is NEVER true.
   The remaining player is permanently trapped on the manual board screen.

USER-FACING IMPACT:
In any online match with custom board design, an opponent quitting or dropping offline
either silently boots the remaining player out without a win, or freezes the game on
the board design screen indefinitely.

REMEDIATION:
Update `inGame` in both packet handlers (lines 2162 and 2239) to include `Screen.ManualBoardDesign.route`:
```kotlin
val destinationRoute = navController.currentDestination?.route
val inGame = (destinationRoute == Screen.Game.route || destinationRoute == Screen.ManualBoardDesign.route)
```

DEFECT ID: BUG-026
SEVERITY : HIGH
MODULE   : In-Game Turn Rotation & Disconnect Timeout Mechanics
FILES    : RootNavGraph.kt (lines 2198, 3900) & LobbyLifecycleEngine.kt (lines 509-520)
--------------------------------------------------------------------------------
DESCRIPTION:
In a 2-player match, if a player disconnects, the disconnect forfeit condition
`misses >= 3` can NEVER be reached. The surviving player is forced to play solo
through the entire board with zero opponent interaction, and is never granted a
forfeit victory.

ROOT CAUSE:
1. When Player B disconnects, they are added to `disconnectedPlayerIds`.
2. Lines 2198 and 3900 check:
   ```kotlin
   if (activeRemaining.size <= 1 && misses >= 3) {
       // Won by forfeit!
   }
   ```
3. On the first turn skip, `misses` is incremented to 1.
4. Turn calculation is executed:
   `val nextId = calculateNextTurnPlayerId(packet.playerId)`
5. In `LobbyLifecycleEngine.kt` (lines 509-520):
   ```kotlin
   val activePlayers = candidatePlayers.filter { candidate ->
       disconnectedPlayerIds.none { dId -> isPlayerIdMatch(candidate.id, dId) } &&
       candidate.lobbyReadyStatus != STATUS_LEFT_LOBBY
   }
   if (activePlayers.size == 1) {
       return activePlayers.first().id
   }
   ```
6. Because Player B is in `disconnectedPlayerIds`, `activePlayers` contains ONLY Player A.
7. `calculateNextTurnPlayerId` unconditionally returns Player A!
8. Player A takes their turn and picks a number.
9. At line 1244 of `RootNavGraph.kt`:
   `val nextPlayerId = calculateNextTurnPlayerId(pickerId)`
   Since `activePlayers` still contains ONLY Player A, `calculateNextTurnPlayerId` returns
   Player A again!
10. Player A is granted turn after turn consecutively.
11. Player B is NEVER assigned the turn again.
12. Because Player B is never the turn player, Player B's turn timer never runs down.
13. `misses` for Player B NEVER increments to 2 or 3!
14. `misses >= 3` is structurally impossible to satisfy in a 2-player match once the
    turn advances to the active player.

USER-FACING IMPACT:
When an opponent disconnects in a 2-player match, the player never receives a forfeit
win after 3 missed turns. They are stranded playing a multiplayer game by themselves
until they manually finish 5 lines of Bingo.

REMEDIATION:
Either:
1. In a 2-player match where `activeRemaining.size <= 1`, declare forfeit victory on
   disconnect (similar to `LEAVE` and `SURRENDER`), or
2. Allow `calculateNextTurnPlayerId` to alternate back to the disconnected opponent
   if `activeRemaining.size == 1` and `consecutiveMissedTurns[opponent] < 3`, so the
   turn timer can cycle through the 3 grace-period missed turns before declaring forfeit.

DEFECT ID: BUG-027
SEVERITY : MEDIUM
MODULE   : Network Lifecycle & Local Persistence
FILES    : RootNavGraph.kt (lines 2443-2454)
--------------------------------------------------------------------------------
DESCRIPTION:
When a player is removed from a room by the host via `KICK_PLAYER`, `OngoingMatchStore`
is not cleared. The kicked player is presented with a persistent "Ongoing Match Detected -
Rejoin Room" banner on the Main Menu. Clicking "Rejoin" triggers an immediate kick loop.

ROOT CAUSE:
In `RootNavGraph.kt` (lines 2443-2454):
```kotlin
"KICK_PLAYER" -> {
    val targetId = packet.targetPlayerId.ifBlank { packet.playerId }
    if (targetId == myUid) {
        Toast.makeText(context, "You were removed from the lobby by the host.", Toast.LENGTH_LONG).show()
        disconnectRoom()
        isHosting = false
        navController.navigate(Screen.MainMenu.route) {
            popUpTo(Screen.MainMenu.route) { inclusive = false }
            launchSingleTop = true
        }
    }
}
```
`OngoingMatchStore.clearOngoingMatch(context)` is omitted.
When the player arrives at `Screen.MainMenu.route`, `MainMenuScreen.kt` queries:
`var ongoingMatch by remember { mutableStateOf(OngoingMatchStore.getOngoingMatch(context)) }`
Finding the match cached on disk, the UI displays the rejoin card:
"Ongoing Match Detected - Room [Code]".
If the user clicks "Rejoin Room", `connectToRoom()` connects back to MQTT. The host still
has the player's UID in `kickedPlayerIds` (lines 739-752 of `OnlineRoomSyncManager.kt`),
which instantly re-broadcasts `KICK_PLAYER`, creating an infinite kick-rejoin loop.

USER-FACING IMPACT:
Kicked players are continually prompted to rejoin rooms they were expelled from, resulting
in repeated error toasts and connection cycling.

REMEDIATION:
Add `OngoingMatchStore.clearOngoingMatch(context)` inside the `KICK_PLAYER` handler:
```kotlin
"KICK_PLAYER" -> {
    val targetId = packet.targetPlayerId.ifBlank { packet.playerId }
    if (targetId == myUid) {
        Toast.makeText(context, "You were removed from the lobby by the host.", Toast.LENGTH_LONG).show()
        com.bingo.multiplayer.domain.network.OngoingMatchStore.clearOngoingMatch(context)
        disconnectRoom()
        isHosting = false
        navController.navigate(Screen.MainMenu.route) {
            popUpTo(Screen.MainMenu.route) { inclusive = false }
            launchSingleTop = true
        }
    }
}
```

DEFECT ID: BUG-028
SEVERITY : MEDIUM
MODULE   : In-Game Lifecycle & Surrender Flow Routing
FILES    : GameScreen.kt (lines 508-513) & RootNavGraph.kt (lines 4331-4365)
--------------------------------------------------------------------------------
DESCRIPTION:
When a player opens the surrender dialog during an active online match and confirms
exit, the app calls `onReturnToLobby` instead of `onSurrender`. This broadcasts
`PLAYER_DISCONNECTED` instead of `SURRENDER` and routes the player back to the lobby
while the opponent remains stranded in the game.

ROOT CAUSE:
In `GameScreen.kt` (lines 508-513):
```kotlin
confirmButton = {
    Button(
        onClick = {
            ...
            if (isMultiplayerLobbyGame) {
                onReturnToLobby?.invoke()
            } else {
                onSurrender()
            }
        }
    )
}
```
In online rooms, `onReturnToLobby` is always non-null (line 4331 of `RootNavGraph.kt`).
Therefore, `onReturnToLobby` is always chosen over `onSurrender`.

In `RootNavGraph.kt` (lines 4341-4365):
```kotlin
onReturnToLobby = if (currentGameMode == GameMode.ONLINE_ROOM ...) {
    {
        val wasOver = isGameOver
        if (wasOver) {
            ...
        } else {
            // Active match in progress:
            OngoingMatchStore.updateMatchGameState(...)
            broadcastPacket(RoomMessagePacket(type = "PLAYER_DISCONNECTED", ...))
        }
        ...
        navController.navigate(targetRoute) // Navigates to Lobby!
    }
}
```
Because `wasOver` is false, `PLAYER_DISCONNECTED` is emitted and the user returns to
the lobby. The remote opponent receives `PLAYER_DISCONNECTED` (which expects a reconnecting
player or 3 missed turns) rather than `SURRENDER` (which awards an immediate forfeit win).

USER-FACING IMPACT:
A player deliberately quitting mid-game does not forfeit cleanly. The opponent is left
in a match expecting a reconnecting player, while the quitter sits in the lobby with
status `NOT_READY`.

REMEDIATION:
In `GameScreen.kt`, during an active match (`!isGameOver`), confirming the surrender
dialog must invoke `onSurrender()` to cleanly concede and forfeit the match. `onReturnToLobby`
should only be invoked when `isGameOver == true`.

DEFECT ID: BUG-029
SEVERITY : LOW
MODULE   : UI & Visual Presentation
FILES    : GameScreen.kt (line 973) & GameOverCelebration.kt (lines 48, 89-93)
--------------------------------------------------------------------------------
DESCRIPTION:
Deprecated `StampResultType.DRAW` enum constant and evaluation branches remain in the
UI layer despite the full decommissioning of draw outcomes from the game rules.

ROOT CAUSE:
Per explicit game rules ("Draw is no longer applicable. Now in the game only Winner,
Runner, and Offline stamps will be there"), ties are strictly broken via turn-pick priority
and line count. However:
1. In `GameOverCelebration.kt`:
   - Line 48 defines `DRAW` in `enum class StampResultType`.
   - Lines 89-93 define amber styling and text `"DRAW!"`.
2. In `GameScreen.kt`:
   - Line 973 contains `isDraw -> StampResultType.DRAW to "DRAW!"`.

USER-FACING IMPACT:
While modern engine calculations ensure `isDraw` is always false, having dead `DRAW`
handling introduces technical debt and risks displaying an unsupported amber "DRAW!"
badge if a legacy packet is parsed.

REMEDIATION:
Remove `isDraw -> StampResultType.DRAW` from `GameScreen.kt` and deprecate or remove
`StampResultType.DRAW` from `GameOverCelebration.kt`, leaving only `WON`, `LOST`,
`RUNNER`, and `OFFLINE`.

DEFECT ID: BUG-030
SEVERITY : MEDIUM
MODULE   : Nearby / Local LAN P2P Network Handling
FILES    : RootNavGraph.kt (lines 2258-2266)
--------------------------------------------------------------------------------
DESCRIPTION:
In a LAN / Local P2P match, if the host disconnects or leaves, the guest is hardcoded
to receive a match LOSS, regardless of match context.

ROOT CAUSE:
In `RootNavGraph.kt` (lines 2258-2266):
```kotlin
if (activeRemaining.size <= 1 || isUsingP2p) {
    isGameOver = true
    val wonByForfeit = if (isUsingP2p) false else (activeRemaining.any { it.id == myUid } || participants.size <= 2)
    didPlayerWin = wonByForfeit
    isDrawMatch = false
    isRunnerMatch = false
    recordFinishedMatch(wonByForfeit)
    com.bingo.multiplayer.domain.network.OngoingMatchStore.clearOngoingMatch(context)
    opponentDisconnectMessage = if (isUsingP2p) "Host disconnected. LAN match ended." else "All opponents left the game."
}
```
Line 2260 explicitly forces `wonByForfeit = false` when `isUsingP2p == true`.
Consequently:
- `didPlayerWin` is set to `false`.
- `recordFinishedMatch(wonByForfeit)` records a LOSS in the guest's statistics.
The host abandoning the LAN match penalizes the innocent guest with a loss.

USER-FACING IMPACT:
When playing over Local Wi-Fi / Hotspot P2P, a guest player is unfairly credited with
a defeat whenever the host leaves or drops connection.

REMEDIATION:
When the host disconnects during an active P2P match, award the remaining guest player
a victory by forfeit (`wonByForfeit = true`), consistent with online rooms:
```kotlin
val wonByForfeit = if (isUsingP2p) true else (activeRemaining.any { it.id == myUid } || participants.size <= 2)
```

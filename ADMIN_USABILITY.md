# Admin usability update

The live console keeps a validated passkey session in this tab across refresh. It checks the existing server session before revealing player data. Setup/recovery sessions are not persisted; expiry, revocation and Lock still remove access. Server limits remain 12 hours and 30 minutes without server activity. Every mutation still requires its own server-issued device approval. No password, recovery code, player snapshot or action proof is stored with the tab session. Storage restrictions retain an in-memory sign-in; a temporary session-check outage keeps the console hidden with an explicit Retry option.

Dark mode uses a pure black page and navigation with neutral raised surfaces; light mode remains available. Desktop/mobile layouts retain all existing controls. Click the status counts to filter, combine build/sync/account filters, clear them together, or press / to focus search. Search accepts @username. A selected app-build filter remains selected when its final player upgrades, showing no matches instead of silently broadening the directory.

App version and build are taken together from one report. A newer saved profile report can supersede an older presence report. Missing fields remain Not reported; the latest release is never substituted for an installed version. Activity identifies MQTT last-seen time separately from a Firebase profile sync. A missing live report is unconfirmed, not invented offline. Snapshot activity ages locally and expires live badges in manual mode without extra network requests. The inspector updates its status/version/activity strip without replacing unsaved profile fields. Profile confirmation lists the exact field changes; existing typed account/record deletion and passkey approval remain.

## Evidence

The actual original UI reproduced four failures: session lost on refresh, mixed version/build, missing-time wording, and non-black dark surfaces. Each now has a permanent browser regression. The original production search selector also reproduced the @username failure; the corrected selector and browser path are checked. The 30 previous browser cases remain; the cache regression intentionally now expects server-validated restoration rather than forced logout. Additional cases cover expired/forged sessions, temporary outage retry, disabled storage, filters and manual status ageing. Existing edit/photo/friends/history/deletion/broadcast/update actions run through the actual protected handler with fictional records and virtual WebAuthn. They do not mutate production accounts. Manual-mode expiry and storage hardening have after-fix production-path tests; no executed pre-fix browser reproduction is claimed for those additions.

SOURCE_MANIFEST.json records actual test counts and unchanged Android build validation. This is a website-only update. No APK rebuild, gameplay change, Worker deployment, Firebase rule change, player migration or GitHub Release is included. Main and Pages receive the clean source/assets; APKs and version feed stay unchanged. Real owner passkey/mobile-device confirmation remains owner acceptance.
